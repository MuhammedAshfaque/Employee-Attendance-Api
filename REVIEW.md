# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Unconditionally returned `{"status": "ok"}` with HTTP 200 without checking MongoDB connectivity. Contract requires 503 when MongoDB ping fails. | Stop MongoDB or provide an invalid URI; `/health` still responded with 200 OK instead of 503. | Added `db.command("ping")` in a `try/except` block, returning 200 on success and raising `HTTPException(503, "Database unavailable")` on failure. |
| 2 | `compute_late_minutes` (lines 33-37) | (1) Did not handle timezones or IST calendar offset; (2) Checked `minutes > 10` after integer floor division instead of elapsed seconds, so `09:40:01` (10m 1s) evaluated to 10 minutes and returned 0 instead of 10 (R2); (3) Did not handle overnight shifts where punch-in is past midnight. | Punching in at `09:40:01` for a `09:30` shift returned `0` instead of `10`. | Converted `punch_in` to UTC/IST with `tzinfo`, verified elapsed seconds strictly exceed 600 (`diff_sec > 600`), and took floor whole minutes since shift start (`int(diff_sec // 60)`). |
| 3 | `compute_work_hours` (lines 40-41) | Used Python's built-in `round()`, which applies banker's rounding (round half to even) on float types, violating rule R4. | Work duration of 2.675 hours rounded to 2.67 instead of 2.68. | Implemented half-up rounding using Python's `decimal.Decimal` with `ROUND_HALF_UP` quantized to `Decimal("0.01")`. |
| 4 | `compute_overtime` (lines 44-47) | (1) Returned overtime for any minutes > 0 (`max(0, ...)`), ignoring the 30-minute threshold in R3; (2) Assumed `shift_end` is on the same calendar day, breaking overnight shifts where `shift_end <= shift_start`. | Punching out 5 minutes after shift end returned `5` instead of `0`. For an overnight shift (22:00-06:00), shift end was treated as 06:00 on the shift start day, yielding ~14+ hours of spurious overtime. | Adjusted `shift_end` date to the next calendar day when `shift_end <= shift_start`, and returned minutes only if `minutes >= 30`, otherwise 0. |
| 5 | `create_employee` (lines 78-85) | Check-then-insert race condition (`find_one` followed by `insert_one`) without a unique database index. Concurrent requests with identical `emp_code` could insert duplicates or crash with unhandled 500. | Sending two simultaneous POST requests with the same `emp_code` resulted in duplicates or 500 Internal Server Error. | Created a unique index on `employees.emp_code` at startup, removed pre-check, and caught `DuplicateKeyError` to return HTTP 409. |
| 6 | `EmployeeIn` & `create_employee` (lines 53-60, 78-85) | (1) Missing input validation rules (`emp_code` pattern `^EMP\d{4,6}$`, email regex, string lengths); (2) Allowed equal `shift_start` and `shift_end`; (3) Stored `created_at` as local naive `datetime.now()` and returned it as datetime instead of integer epoch milliseconds. | Submitting `shift_start: "09:00", shift_end: "09:00"` succeeded with 201 instead of 422; response `created_at` was not an integer. | Replaced with strict Pydantic model with field validators (including `shift_start != shift_end`), stored UTC BSON date, and serialized `created_at` to epoch milliseconds. |
| 7 | `list_employees` (lines 88-96) | (1) Off-by-one pagination: `skip = page * page_size` skipped the first page on `page=1`; (2) `total` counted the whole collection instead of matching the filter `q` (violating R10); (3) Unsorted results; (4) Missing validation for `page >= 1` and `page_size <= 100`; (5) `created_at` not formatted to epoch ms. | Calling `GET /employees?page=1` skipped items 1-20; filtering by department showed the total count of all employees in the database. | Set `skip = (page - 1) * page_size`, used `count_documents(q)`, added `.sort("emp_code", 1)`, added Query validation, and formatted items. |
| 8 | `punch_in` (lines 99-121) | (1) Check-then-insert race condition without unique index; (2) Crashed with 500 `TypeError` if employee did not exist (`emp["shift_start"]` on `None`); (3) Did not truncate `punched_at` to whole seconds (R1); (4) Used server local date instead of IST date; (5) Ignored overnight shift assignment; (6) Allowed invalid status values; (7) Injected non-schema `id` field and returned unformatted datetimes. | Punching in for unknown employee threw 500; concurrent punch-ins created duplicates; punch times were not epoch ms integers. | Created unique index on `(emp_code, date)`, added 404 check, validated status enum, truncated timestamps to whole seconds, applied IST and overnight shift rules, and serialized output according to `AttendanceRecord`. |
| 9 | `list_attendance` (lines 124-150) | (1) Loaded entire collection into Python memory with `list(db.attendance_logs.find(q))` and sorted in Python, which exhausts memory and violates the 100k performance requirement; (2) Missing secondary sort `emp_code` ascending; (3) Did not return 422 when `date_from > date_to`; (4) Injected `id` field; (5) Unformatted datetimes and missing defaults for legacy records. | Querying `GET /attendance?date_from=2026-07-10&date_to=2026-07-01` returned 200 instead of 422; high memory and response latency on large datasets. | Performed sorting `.sort([("date", -1), ("emp_code", 1)])` and pagination `.skip().limit()` directly in MongoDB backed by indexes; added 422 validation for invalid date range; properly formatted records. |
| 10 | MongoDB Client initialization (lines 22-23) | Initialized without `tz_aware=True`, causing PyMongo to return naive datetimes that lead to silent offset errors across UTC and IST calculations. | Mixing naive BSON datetimes with timezone-aware instants raised TypeError or produced incorrect date calculations. | Initialized `MongoClient(MONGO_URI, tz_aware=True)` and normalized all instant conversions at API boundaries. |

### Things examined and decided were NOT defects:
- **`app = FastAPI(title=..., version="2.0.0")`**: Root FastAPI application configuration correctly reflects the assignment version and title.
- **Natural key identifying employees**: Addressing employees by customer `emp_code` and attendance records by `(emp_code, date)` without exposing MongoDB `_id` in request/response bodies matches the architecture contract.
- **Collection naming**: Using `employees` and `attendance_logs` matches the seeded dataset and `DATA_MODEL.md`.
